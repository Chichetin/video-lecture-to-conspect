# Задача

Подготовь учебник по вопросам к защите лабораторной работы. Аргументы: `$ARGUMENTS`
1 — папка лабы (например, `labs/db-2/`), в ней лежит **PDF с условием**: требования к работе и список вопросов (обычно в конце);
2 — необязательно: ссылка на репозиторий с решением (GitHub/GitLab, `https://…` или `git@…`);
`--pdf` — дополнительно собрать PDF.
Чтобы учебник попал на сайт конспектов (шаг 8), папка должна называться `<префикс курса>_lab<N>`, например `labs/web_lab2`.
Если папка не передана — посмотри `labs/`: если там ровно одна папка без `primer.md`, бери её и скажи об этом; иначе спроси.

Обозначения: `L` — папка лабы, `W` = `L/work`.

**Выход** (в `L`):
1. `primer.md` — учебник: по разделу на каждый вопрос из PDF;
2. `report.md` — что сделано, допущения, расхождения, слабые места;
3. только с `--pdf`: `output/<имя папки>_questions.pdf` в корне проекта.

Если в папке нет PDF или их несколько и непонятно, где условие, — спроси и не начинай.

# Жёсткие правила

1. **Все вопросы, дословно и по порядку.** Ни один вопрос из PDF не пропускается, не объединяется с другим, не переставляется и не перефразируется.
2. **Репозиторий — только для чтения.** Не запускай из него ничего (сборка, тесты, скрипты, `npm install`, `docker`), не ставь зависимости, не пушь. Секреты из него (пароли, токены, ключи, строки подключения) не выводи и не цитируй.
3. **Не угадывай стек молча.** Если по PDF и репозиторию неясен стек или вариант (фреймворк, язык, СУБД) — задай пользователю один уточняющий вопрос до плана.
4. **Честность.** Не выдумывай, как сделано в работе: про «твою работу» — только то, что есть в репозитории или в условии. Лекции курса (`lectures/`, `course.md`) не используются.

# Правила учебника

Назначение, голос, устройство раздела, разметка, схемы Mermaid и структура документа — в `.claude/lab/primer.md`; эталон разметки — `.claude/lab/sample.md`. Прочитай оба до плана: ты пишешь вступление и правишь разделы по тем же правилам.

# Шаг 0. Подготовка

- Проверь Python-пакет `pymupdf` (`import pymupdf`) и `git`. С `--pdf` — ещё `pandoc`, `xelatex` и `mmdc` (Mermaid CLI). Без `mmdc` PDF соберётся, но схемы в нём будут кодом; установка: `npm i -g @mermaid-js/mermaid-cli`. Чего нет — сообщи с командой установки (пользователь может выполнить её через `! …`).

# Шаг 1. Условие

- Текст каждой страницы PDF через PyMuPDF → `W/task.json` (`[{"page": N, "text": "...", "low_text": bool}]`). Страницы почти без текста отрендери в `W/pages_png/NN.png` (~100 dpi) и посмотри картинками.
- Прочитай условие целиком (оно короткое) и выдели: номер и название работы, дисциплину, предметную область (что за система, какие сущности и поля), требования, вариант, стек.
- Вопросы → `W/questions.json` (`[{"n": 1, "text": "дословная формулировка"}]`). Нумерация — как в PDF; если в PDF вопросы без номеров — по порядку. Если вопросы выделяются неоднозначно (скан, сбитая нумерация, вопросы вперемешку с заданиями) — покажи пользователю список и дождись подтверждения.

# Шаг 2. Репозиторий (если передан)

- `git clone --depth 1 <url> W/repo`; если не вышло (приватный) — `gh repo clone <url> W/repo -- --depth 1`; если и так не вышло — скажи пользователю и спроси, продолжать ли без репозитория. Если `W/repo` уже есть — используй его, не клонируй заново.
- Коммит: `git -C W/repo rev-parse --short HEAD`.
- `W/repo_map.md`: стек и версии (по `pom.xml`, `build.gradle`, `package.json`, `requirements.txt`, `pyproject.toml` и т. п.), дерево значимых файлов (`git -C W/repo ls-files`, без сгенерированного, ресурсов и vendor), по строке на ключевой файл — за что отвечает; какие требования условия где реализованы и какие не реализованы. Большие файлы читай частями; репозиторий целиком в контекст не выводи.

# Шаг 3. План `W/plan.md`

Задай уточняющий вопрос, если нужно (жёсткое правило 3). Затем запиши план:
- шапка: работа, дисциплина, вариант, стек, предметная область (сущности и поля — их используют все примеры кода), список требований условия (с номерами пунктов, если они есть), репозиторий и коммит или «без репозитория»;
- по каждому вопросу: `n`, формулировка, что покрыть (подтемы, все термины формулировки), какие требования условия закрывает, файлы репозитория для блока «В твоей работе» (или «в работе не задействовано»), известные расхождения с практикой, связи с другими вопросами («опирается на 3», «подробнее — 7»), схемы (тип и что показывают; 10–15 на документ), ориентир объёма в словах (обычно 600–1500, по ширине темы).

Темы, общие для нескольких вопросов, закрепи за одним разделом, а остальным назначь ссылку на него — так не будет повторов.

# Шаг 4. Разделы

- Субагенты `lab-section` (через Agent с этим `subagent_type`; правила они читают сами, в задании — только входные данные). Каждому — «`L`, вопрос `n`, ориентир ~N слов»; короткие родственные вопросы можно отдать одному субагенту по 2–3 («`L`, вопросы 4, 5, 6, ориентиры …»). Запускай параллельно. Результат — `W/sections/NN.md`. Если субагент упал с ошибкой API — перезапусти его тем же заданием. Если агента нет (сессия запущена до его появления) — скажи пользователю перезапустить Claude Code.
- Из ответов субагентов собери для отчёта расхождения, допущения и слабые места.

# Шаг 5. Сборка `primer.md`

- `W/primer_head.md`: YAML и вступление по разделу «Структура документа» в `primer.md`; `W/primer_tail.md`: `***` и итоговая строка.
- `L/primer.md` = head + `W/sections/*.md` по порядку + tail (скриптом).
- `python tools/lab_check.py L` — число, порядок и формулировки разделов против `questions.json`, ссылки `#qN`, типы схем и плашек, запрещённая разметка. Исправь все проблемы в `W/sections/*.md` и пересобери.
- Прочитай `primer.md` целиком и проверь связность: термин используется после того, как объяснён (или со ссылкой на раздел, где объяснён), нет повторов между разделами, ссылки ведут туда, где тема действительно раскрыта, примеры кода — на одной предметной области и согласованы (одни и те же имена сущностей и полей), голос выдержан. Правки вноси в `W/sections/*.md` и пересобирай.

# Шаг 6. PDF (только с `--pdf`)

`tools/latex/build.sh L primer.md questions` → `output/<имя папки>_questions.pdf`. Шаблон и фильтр — `tools/latex/conspect.tex`, `conspect.lua` (режим `doc-kind: lab`); схемы Mermaid рендерятся через `mmdc` в `W/mermaid/`. Ошибку сборки чини в разметке раздела или в фильтре; лекционную часть шаблона не меняй. Схема, которую `mmdc` не смог отрисовать, остаётся в PDF кодом — поправь её синтаксис в разделе.

# Шаг 7. Отчёт

`L/report.md` и короткое сообщение в чате (учебник не пересказывай, без похвалы):
1. где требования условия расходятся с общепринятой практикой и что с этим делать на защите;
2. какие допущения сделаны (стек, вариант, трактовка неоднозначных формулировок);
3. слабые места учебника: что раскрыто поверхностно, что намеренно не включено и почему;
4. в отчёте дополнительно: число вопросов и схем, объём, использован ли репозиторий (коммит), требования условия, не реализованные в репозитории, проблемы по ходу.

# Шаг 8. Сайт конспектов

Если рядом есть сайт (`../conspects-online/sync.py`), выполни `python ../conspects-online/sync.py`: он забирает последние версии всех лекций и лабораторных из `lectures/` и `labs/` в `content/` сайта; учебник без PDF публикуется с пометкой «PDF пока недоступен», PDF подхватится при следующем запуске после `--pdf`. Если скрипт остановился на неизвестном префиксе курса — спроси у пользователя название курса и добавь запись в `../conspects-online/courses.toml` (ключ — префикс, `slug` латиницей, `title`, `color`), затем запусти снова. Покажи `git -C ../conspects-online status --short` и предложи закоммитить и запушить `content/` (и `courses.toml`, если менялся): push публикует сайт, поэтому коммить и пушь только после явного согласия пользователя. Если папки сайта нет — пропусти шаг.
